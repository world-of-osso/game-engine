# City model receipt probe

1. Place a private account's character at the target map and position with `game-server-admin set-position` while it is offline. Start a rendered client under `scripts/agent/agent-run` and the host's `client-slot.sh`, using `godot/tests/receipt_city_probe.gd` as its script. Set `GODOT_TEST_SERVER`, `BENCH_ACCOUNT`, `BENCH_CHARACTER`, and `BENCH_SCREENSHOT` (a path prefix). The fixture requires a 1920×1080 hardware-rendered viewport, waits for the world queues to drain, and prints `ZONE_REPORT` and every asset error. Missing receipts are reported, not treated as a successful render.
2. Collect unique Retail M2 FDIDs from `No verified asset receipt for wow FDID <id>.m2` log lines in a JSON array. The count is a sampled frontier, not a whole-zone census.
3. Stage the observed model chains privately with `GAME_ENGINE_ASSET_MODE=extracted-only SIBLING_GAME_SERVER=<server-checkout> scripts/agent/agent-run <agent> python3 scripts/performance/stage-observed-models.py --roots <roots.json> --output <new-private-directory> --canonical-data <canonical-data> --install <local-wow-install> --extractor <installed-casc-local>`. It authenticates the active local CASC root and content keys, uses the existing producer graph and local decoder, and does not publish into canonical data. Inspect `model-closure/summary.json`, source gaps and the staged fragment before publishing. The graph's raw producer identity is not an offline audit; its staged payloads are separately content-key verified.
4. Existing root receipts can still lack their build-qualified companions. For roots owned by one historical build, run `SIBLING_GAME_SERVER=<server-checkout> scripts/agent/agent-run <agent> python3 scripts/performance/stage_frozen_model_closure.py --source-data <flat-data> --index-data <indexed-data> --roots <roots.json> --manifest <frozen-source-manifest> --root <frozen-root.bin> --resolution <frozen-resolution.sqlite> --output <new-private-directory> --name <zone-date>`. The producer verifies the frozen snapshot and each root receipt, expands all authored model dependencies, verifies source bytes against frozen content keys, and stages unique assets and aliases. It fails if a required dependency cannot be authenticated; it does not extract or publish data.
