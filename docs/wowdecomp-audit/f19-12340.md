## Q-F19-1 — ActionStatus and screenshot events

**What W establishes:** `CGWorldFrame::RegisterFrames` registers the native `WorldFrame` factory, but no `ActionStatus` frame/mixin or Lua callback is present in the pinned reconstruction. `CGGameUI::HandleScreenshot` returns before signaling unless game UI is initialized; then it emits `SCREENSHOT_SUCCEEDED` or `SCREENSHOT_FAILED` according to the completion result. W's event table assigns IDs 171 and 172 respectively. The searched W tree contains no `SCREENSHOT_STARTED` or `ActionStatus` name. This is a reconstruction-bounded absence, not proof that shipped 12340 FrameXML lacked them.

**Separate 3.4.3 source:** `Interface/FrameXML/WorldFrame.xml:21,42–67` declares an `ActionStatus` child `<Frame>` (not a mixin) with `OnLoad`, `OnEvent` and `OnUpdate` callbacks. `WorldFrame.lua:87–127` defines `ACTION_STATUS_FADETIME = 2.0`, `ActionStatus_OnLoad`, `ActionStatus_OnEvent`, `ActionStatus_DisplayMessage` and `ActionStatus_OnUpdate`. OnLoad registers `SCREENSHOT_STARTED`, `SCREENSHOT_SUCCEEDED` and `SCREENSHOT_FAILED`; started hides the frame. The other events reset time/alpha; success/failure route localized text through `ActionStatus_DisplayMessage(..., true)` and show the frame. The display helper otherwise checks `showNewbieTips`; OnUpdate fades alpha linearly for two seconds, then hides. This answers the behavior of that tagged 3.4.3 source only. Whether the same frame, globals, start event or transition shipped in 12340 remains unknown.

Evidence W: `WoW/Source/Ui/WorldFrame.cpp:1281–1289`; `WoW/Source/Ui/GameUI.cpp:4281–4293`; `WoW/Source/Ui/Types.h:841–842`. Separate UI-3.4.3 source: `Interface/FrameXML/WorldFrame.xml:21,42–67`; `Interface/FrameXML/WorldFrame.lua:87–127`.

## Q-F19-2 — World-map quest POIs and checkbox paths

W exposes native quest/map state, but not the target FrameXML selectors or callback order:

- `QuestMapUpdateAllQuests()` resolves the current area from continent/zone/orphan-map state; for an eligible area/dungeon it calls `CGQuestLog::UpdateAllQuestPOI()` and returns the resulting numeric count. That native routine checks the POI CVar and active player, then filters up to 25 POIs by objective mask, floor, area/map or dungeon visibility.
- `QuestPOIUpdateIcons()` calls `CGQuestLog::UpdatePOIIcons()` and returns no Lua values. For each quest, the native routine filters its blobs by objective/floor/map visibility, selects the lowest numeric blob priority, and breaks equal-priority ties by nearest squared XY distance to the player; it then records icon map/floor/coordinates, separates active from complete markers, applies overlap forces to active markers and configured shifts to clustered complete markers.
- `QuestPOIGetQuestIDByIndex(index)` accepts the 1-based slot index 1–25 and returns its stored quest ID when valid; invalid slots return no Lua values. `QuestPOIGetQuestIDByVisibleIndex(index)` maps a 1-based visible index to a quest ID and quest-log index. Its native selector orders visible completed/no-objective POIs first, watched active quests next, then other visible active POIs.
- `QuestPOIGetIconInfo(questID)` returns completion, map Y, map X and floor when POI data and coordinate conversion succeed; otherwise it returns no values. `QuestPOIUpdateTexture()` is registered but its native handler is a no-op.
- Native map-state updates emit `WORLD_MAP_UPDATE` after map/overlay processing; quest-POI response parsing emits `QUEST_POI_UPDATE` after blob data is populated. These producer-side event points do not establish which Lua callbacks ran, or their order.

W has no version-matched `WorldMapFrame.lua/xml`, so exact 12340 FrameXML callbacks, selectors, checkbox texture paths and their order remain unknown. The local 3.4.3 tag has `Interface_Wrath/FrameXML/WorldMapFrame.xml`, which only includes `WorldMapPOIQuantizer.lua`; its Wrath TOC separately lists `WorldMapFrame.xml` and `QuestMapFrame.xml`. Those files do not authenticate 12340. No matching checkbox path can be recovered from W's C++ source.

## Q-F19-3 — add-on dependencies and named UI systems

W's generic loader parses `OptionalDep*` into optional dependencies and `RequiredDep*`/`Dep*` into required dependencies. `LoadAddOn` attempts optional dependencies first (ignoring failure), then required dependencies (failure aborts the parent before its files load), loads the add-on TOC, signals `ADDON_LOADED`, then loads `LoadWith` dependants. Startup creates base `FrameXML.toc` before `LoadAddOns`. Exact searches of W found no `Blizzard_MapCanvas`, `VoiceChatPrompt` or `SocialToast` names. This proves a generic dependency mechanism exists in the reconstruction; it does not prove specific addon metadata or a 12340 analogue.

They are **not Mainline-only in the later 3.4.3 UI source**: `Blizzard_WorldMap_Wrath.toc` requires `Blizzard_MapCanvas` and `Blizzard_SharedMapDataProviders`; `Blizzard_Channels.toc` includes `VoiceChatPrompt.xml`; `VoiceChatPrompt.xml` inherits `SocialToastTemplate`; and `FrameXML_Wrath.toc` includes `SocialToast.xml`. This establishes availability in the tagged 3.4.3 snapshot only. Whether 3.3.5a/12340 had these named components or functionally similar dependencies is unresolved without matching addon TOCs and FrameXML.

Evidence W: `WoW/Source/UIUtil/AddOns.cpp:1003–1108,1113–1124,1195–1223`; `WoW/Source/Ui/GameUI.cpp:1760–1797`. Separate UI-3.4.3 source: `Interface/AddOns/Blizzard_WorldMap/Blizzard_WorldMap_Wrath.toc:1–4`; `Interface/AddOns/Blizzard_Channels/Blizzard_Channels.toc:9`; `Interface/AddOns/Blizzard_Channels/VoiceChatPrompt.xml:3–5`; `Interface/FrameXML/FrameXML_Wrath.toc:213`; `Interface/FrameXML/BNet.xml:6,86`.
