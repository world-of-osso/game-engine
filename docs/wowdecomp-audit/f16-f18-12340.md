### 2. `UnitBuff` tuple and `GetPlayerAuraBySpellID`

W registers legacy `UnitBuff`; its wrapper parses unit plus index-or-name/rank and forces the helpful filter (`WoW/Source/Ui/ScriptEvents_Scripts.cpp:2677–2686`). The shared parser converts numeric aura indices from 1-based to 0-based, accepts a name with optional rank, defaults to helpful, and parses helpful/harmful/player/raid/cancelability filter tokens (`WoW/Source/Ui/ScriptEvents.cpp:976–1039`).

For a resolved native unit, `PushUnitAura` returns 11 values in this order: spell name, rank/subtext, icon filename, stack count, dispel-type name, duration seconds, expiration seconds, caster unit token, stealable marker, consolidation marker, spell ID. Duration and expiration are zero when native duration is nonpositive; marker values are numeric `1` or nil (`ScriptEvents.cpp:1042–1099`). Party-state fallback also returns 11 values, but uses stack count `1`, zero duration/expiration, nil caster and nil stealable marker; its consolidation marker and spell ID occupy positions 10 and 11 (`:1103–1178`). Missing or filtered aura returns zero Lua results. This is the reconstructed legacy behavior, not a runtime comparison.

No `GetPlayerAuraBySpellID` registration or declaration was found in W. That does not establish whether a shipped Lua file defined it; exact target API availability remains unknown.

### 3. `AddMessage` timing and message count

W registers distinct `MessageFrame` and `ScrollingMessageFrame` native factories (`Engine/Source/FrameXML/FrameXML.cpp:412–415`). Plain `MessageFrame:AddMessage` copies text/color into a pending queue (`Engine/Source/Frame/CSimpleMessageFrame_Scripts.cpp:304–325`; `CSimpleMessageFrame.cpp:250–259`). `OnLayerUpdate` drains that queue only when `GetRect` succeeds (`CSimpleMessageFrame.cpp:347–368`); the binding returns no message count and the inspected plain-frame API has no `GetNumMessages` query.

`ScrollingMessageFrame:AddMessage` writes its ring-buffer line and updates `m_numMessages` during the call (`Engine/Source/Frame/CSimpleMessageScrollFrame_Scripts.cpp:189–249`; `CSimpleMessageScrollFrame.cpp:830–887`). Its `GetNumMessages` binding reads that count (`CSimpleMessageScrollFrame_Scripts.cpp:398–402`; `CSimpleMessageScrollFrame.cpp:149–168`). Thus scroll-frame history/count is synchronously populated, while plain-frame insertion is deferred until a layer update with valid geometry; visible pixels still depend on rendering. W does not establish which type `DEFAULT_CHAT_FRAME` uses in target 12340. The separate 3.4.3 `Interface/FrameXML/ChatFrame.xml:4` declares `ChatFrameTemplate` as a `ScrollingMessageFrame`, but that is not 12340 evidence.

### 4. `party1`–`party3` resolution and aura lookup

W maps `partyN` to `GetPartyMember(N - 1)` (`WoW/Source/Ui/ScriptEvents.cpp:125–145`). The party GUID array has four slots; `GetNumPartyMembers` counts occupied slots. `AddMember` fills the first empty slot, copies supplied party state (or initializes health/power defaults), and sets/clears its online flag (`WoW/Source/Ui/PartyFrame.cpp:103–145,689–716`). This is token/state resolution, not proof of when the client activates a UI frame or populates a slot.

`PushUnitAura` first uses a live native unit object when one resolves; otherwise it looks up cached party-member or pet state by GUID. The member-state path returns no aura when its online flag is clear; absent state also returns no aura. Cached aura entries are filtered and projected into the 11-result legacy shape described above (`ScriptEvents.cpp:1042–1178`). Exact 12340 Lua frame activation and event timing remain unknown.

## F18 — container initialization, item tuple, tradeskills, currency UI

### 1. Container/backpack initialization and event order

In W, `CGGameUI::EnterWorld` emits `PLAYER_LOGIN` first only when logging in, then emits `PLAYER_ENTERING_WORLD`; after that event dispatch returns, it calls `CGMinimapFrame`, `CGChat`, `CGActionBar`, `CGCharacterInfo`, then `CGContainerInfo::EnterWorld` (`WoW/Source/Ui/GameUI.cpp:3713–3758`). `FrameScript_SignalEvent` iterates registered listeners and calls `FrameScript_Execute` inline (`Engine/Source/FrameScript/FrameScript.cpp:1447–1484,1512–1570`), so Lua `OnEvent` listeners for those signals run synchronously at the signal call site.

`CGContainerInfo::EnterWorld` installs player-inventory mirror handlers, clears its 11 equipped-container GUID entries, then calls `UpdateContainers` (`WoW/Source/Ui/ContainerFrame.cpp:28–53`). `UpdateContainers` reads equipped-container GUIDs from player slots 19–22 and 63 onward; for each changed nonempty container it registers content handlers before signaling `BAG_UPDATE` with index `i+1` (`:376–418`). Player inventory content updates signal bag indices `0`, `-2` and `-4`; equipped-container content updates signal the matching positive index (`:201–216`).

`GetLuaBagAndSlot` converts script arguments to zero-based values. `(bag=0, slot=1)` maps to the player's internal bag slot 23 (`ContainerFrame.cpp:131–184`). These native paths establish data lookup and event ordering, not when target `ContainerFrame_OnLoad` creates buttons or synchronously paints their icons. The target Lua/XML/TOC event registration and button-update path remain unavailable.

The separate 3.4.3 `Interface/FrameXML/ContainerFrame_Shared.lua` handles `BAG_UPDATE` by calling `ContainerFrame_Update` (`:49–52`); `ContainerFrame_OnShow` calls `ContainerFrame_Update` before returning (`:222–295`, update body `:490–635`). This is later cache behavior only. Its `Interface_Wrath/FrameXML/MainMenuBarBagButtons.xml:43–56` also registers `BAG_UPDATE_DELAYED`; W's source-side findings above establish `BAG_UPDATE`, not that later UI event path.

### 2. Legacy `GetContainerItemInfo` tuple

For a present item, W's `GetContainerItemInfo(bag, slot)` returns seven values: inventory-art texture path, stack count, locked marker (`1` or nil), quality (or `-1` when item stats/inventory type do not resolve), readable marker (`1` or nil), a second item flag (`1` or nil, sourced from static flag bit `0x4`), and hyperlink. Missing bag/item returns zero Lua results (`WoW/Source/Ui/ContainerFrame_Scripts.cpp:180–240`). It is a path/string API, not an icon fileDataID or the later `C_Container` info table. The `(0,1)` backpack lookup resolves to internal slot 23 as above; this confirms what the binding reads, not whether a target UI button has refreshed its own identity/icon.

The separate 3.4.3 container Lua uses later `C_Container` table fields, including `iconFileID` and `stackCount`. Do not use that cache shape as the 12340 return contract.

### 3. Trade-skill show/load sequence

This establishes the conditional native event, not that a target UI frame exists, loads or becomes visible.

### 4. Currency API and backpack tracker ownership
