## A4: General authored events lose dispatch, timing context and payload

**Reference.** `W/Engine/Source/Model2/M2Model.cpp:5906–5978` traverses authored event timestamps, selects sequence-indexed timestamps or array zero according to the track selector, filters the relevant bone ancestry and queues identifier, data and bone identity. At dispatch, authored position is transformed by the current bone matrix and scene inverse view; callback time is `callbackTime - eventTime`. The routine's call to `Animate()` does not itself establish pose sampling at the event timestamp or an independent global-clock interval. The callback queue is invoked at `:6438–6453`, processed recursively at `:6457–6561`, with the scene reaching callback processing at `W/Engine/Source/Model2/M2Scene.cpp:62`.

**Current subset.** `E/godot/core/src/asset/m2_format/m2_event.rs:24–75` retains identifier, data, bone, position and timestamps, but not the track's global-sequence selector. Native `E/godot/rust/src/animation/action.rs:29–35,69–103` selects only `$SCD/$CSS/$CAH` action notifications and the first `$CSL/$CSR/$CST` missile-release time. `:244–256` reports passed action events as identifiers only. `E/godot/rust/src/world_combat.rs:303–312` carries unit identity plus identifier to `E/godot/rust/src/spell_melee.rs:99–112`; this is real partial support, not a general event record dispatch. Ordinary sequence advancement at `E/godot/rust/src/animation/mod.rs:648–706` has no corresponding authored-event traversal.

**Required change.** Preserve and dispatch the supported authored event contract over the actually traversed interval, including timestamp-array selection, event data, dispatched bone ID and reference-equivalent transformed position/relative time. Preserve the track selector without assuming its event semantics equal the separate global animation-track clock. Extend beyond the selected action notifications without duplicating the existing missile/melee/voice behavior. Do not invent effects for unknown event IDs: general dispatch and individual event-effect handlers are separate coverage boundaries.

**Acceptance.** A looping ordinary sequence has an event at 100 ms with a known identifier, payload, bone 2 and a nonzero bone-relative position. Advance 90→110 ms and observe exactly one event with its authored fields, the bone ID corresponding to authored bone index 2, and position transformed by the reference's bone matrix and scene inverse view at dispatch. Repeat across a wrap, several timestamps in one update, sequence replacement and a track selector choosing timestamp array zero. Respect `(start,end]` firing boundaries and the reference relative callback time; events outside the traversed interval must not fire. Do not assert event-time pose reconstruction or an independent global-clock interval without additional evidence. Include the existing six action/missile IDs as regression controls. This proposes an observable event fixture, not proof that every event ID has a gameplay handler or that an affected asset was observed.

## A5: Replay bounds do not control finite sequence residence

**Reference.** `W/Engine/Source/Model2/M2Model.cpp:1572–1614` chooses an authored replay count, promotes zero to one, and stores both that count and an end time based on `repeats × sequence duration / speed`. Finite-sequence sampling/completion consumes that end time at `:5131–5154,6497–6517`; the finite branch uses sequence flag `0x1`. Indefinite loops use a different callback branch, so repeat bounds do not establish universally delayed variation decisions for every loop mode. Preserve the actual integer selection formula; its upper-bound arithmetic must not be replaced with an assumed inclusive random range.

**Current.** `E/godot/core/src/asset/m2_format/m2_anim.rs:112–122` retains replay bounds. `E/godot/rust/src/animation/mod.rs:648–706` clamps a non-looping clip after one duration, wraps an ordinary loop by modulo, or chooses a variation at each single-duration boundary. No replay budget delays completion or variation reselection in this path.

**Required change.** Honor authored replay residence for finite playback and any separately established repeat-aware selection path, while sampling within repeated clips correctly. Do not impose finite completion semantics on every indefinite loop. Preserve default zero-bounds behavior, playback speed, continuous crossfades and already implemented variation-family probabilities. This is missing repeat scheduling, not missing variation parsing.

**Acceptance.** Use a reference finite sequence (flag `0x1`), duration 100 ms and deterministic bounds `[3,3]` at speed 1. Measure elapsed time from its stored start time: its residence budget is 300 ms, not 100 ms. Its pose cycles at 100/200 ms but finite completion must not occur early. Check any ensuing selection only at the reference's applicable completion boundary. Check 299→300 ms, `[0,0]` minimum-one behavior, non-unit playback speed and a large elapsed interval. Use fixed equal bounds first so the reference's random-range endpoints cannot invalidate the test. Real-asset incidence and native proof remain unknown.
