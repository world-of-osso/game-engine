# Talents

PlayerSpellsFrame displays and edits the existing server talent configuration. Modern and Forever expose identical elements and behavior; Forever changes art only. [Local graph/layout provenance](../wiki/systems/talents.md).

## Required behavior

- Map class SkillLine (category 7) through SkillLineXTraitTree variant 0; filter local DB2 nodes/entries by spec visibility, retaining ordered choices, prerequisites and hero trees.
- Receive `TraitConfigSnapshot` on the owning account. Display committed total ranks (including grants) and server unspent class/spec points. Each new snapshot replaces pending edits, closes the choice flyout and clears errors.
- Left-click stages one rank. Right-click refunds one purchased rank, never a grant. Tiered nodes follow DB2 entry order in both directions, not the sorted wire IDs. Choice nodes open a flyout; choosing stages exactly one entry. Hero selection uses the same choice flow.
- Reject unavailable edits locally: entry maxima, required/sufficient prerequisite edges, conditions, earlier-row currency gates, level budgets, selected hero subtree and available points. The server remains authoritative.
- Apply Changes sends one `CommitTraitConfig` containing the specialization and complete pending entry list with total ranks. No node click sends a request or casts a spell.
- Undo discards pending edits and restores committed state. Undo replaces Reset at their shared Retail anchor while changes exist. Reset opens Retail's class/spec/all menu; resetting stages removal of purchases in the selected main tree(s), preserves granted ranks and hero talents, and requires Apply for persistence.
- Both skins expose Retail's loadout dropdown and SearchBox at the footer. Default Loadout is the active unnamed configuration caption, not a fabricated saved row. Named rows and selected caption come only from the server's per-spec loadout list. New copies the current staged allocation into a persisted named config; row gear opens rename/delete, deletion requires confirmation, and switching with pending edits requires discard confirmation. Only server snapshots change the selected caption and committed ranks. See [loadouts contract](talent-loadouts.md). Do not synthesize saved builds from DB2 starter allocations.
- Search requires Retail's minimum three characters and previews up to three real entry names/icons with an overflow count. Mouse hover and Up/Down select the preview row; Enter selects that row or submits the typed text, then releases edit focus. Selecting a result or pressing Enter activates case-insensitive name/description/related-name matching across eligible nodes, including unselected choices. Inactive eligible hero subtree matches mark the hero selector. Clear removes the active search; focus loss hides previews. Match badges use Retail's exact/name/related/Not-on-Action-Bar atlases. Not on Action Bar searches allocated non-passive spells against replicated action slots.
- A failed `TraitCommitResult` displays its supplied reason on the page and through the existing world error text path. Only a snapshot changes committed ranks; success alone does not assume acceptance state.
- Preserve local icons, shapes and relative /10 graph spacing. Align class/spec first rows at the126px baseline below their currency labels; apply the existing horizontal pan. Apply one uniform class/spec zoom when painted button/rank bounds exceed the Retail node area (856 high minus82 footer); never clip lower nodes or move the footer to cover them. StateBorder uses Retail atlas draw dimensions:40px ordinary overrides, padded84/80px capstone art around its64px hit target. Do not resample away the capstone's transparent rim padding. SpendText uses Mainline's bottom-right x11/y4 anchor (capstones x2/y−10), not LegionInfinite x14/y6, with bottom-aligned Arial Narrow16/18px Roman fonts (SystemFont16/SystemFont22) and thick black outline; include the outline in footer clearance; disabled Apply retains explicit readable50%-grey text without enabling its action. Keep Retail Reset/Undo at its shared footer anchor:20px atlas icon centered in the25px hit rect. Reset is the authored red Retail sprite, not an error overlay. Modern Apply uses UIPanelButtonNoTooltipTemplate's UI-Panel-Button files and12px caps, not defaultbutton-nineslice atlases; Forever may re-skin the same button. Shared spell hover remains available.
- Hero options come only from the spec-visible subtree-selection node's ordered entries. Display its two eligible trees in separate columns in the970×832 Retail selection dialog; display only the selected subtree on the main page. Never stack unrelated/unselected trees. Selection keeps the existing staged-edit flow.

## Implementation

`godot/core/src/talent_data.rs` loads the visual graph. `talent_data/rule_loader.rs` reads raw CSV rule metadata; `rule_data.rs` and `rules.rs` port the existing game-server trait data/evaluator without changing server validation. Keep this port aligned with `game-server/crates/server/src/trait_config.rs`; do not invent alternate client talent rules.

`godot/ui-model/src/talent_editor.rs` owns committed/pending allocations, point deltas and requests. The account owns one editor per connection; actual specialization changes clear it until the new snapshot. A current-spec echo from a rejected request preserves that configuration. A grouped TalentChannel relay preserves spec/result/snapshot order across typed receiver buffers. `talents.rs` projects it into the shared page. NetworkBridge receives both server talent messages and the account sends commits on `TalentChannel`.

## Exclusions and known gaps

Named loadout creation/save/switch/import, Starter Build activation, PvP talents and Warmode require server/protocol capabilities not currently exposed. Export currently lacks a supplied serialization version/tree hash contract and stays disabled; do not emit guessed Retail strings. Blizzard_ClassTalentImportExport.lua:1-46,74-102,166-177 defines the 8-bit version/16-bit spec/128-bit hash header, all-class-node ascending-ID order and selected/purchased/partial-rank/choice bits; Blizzard_SharedXMLBase/ExportUtil.lua:31-69 packs least-significant bits into the base64 alphabet without byte-oriented base64 padding. The documented third-party zero hash is allowed, but is not a substitute for a supported serialization version. The footer reserves Retail's82px bounds; only the chosen subtree is purchasable. Missing or invalid shipped icon files are explicit asset errors under the [spell icon contract](spellbook-action-bar.md#spell-icon-source), never accepted empty slots or substitute art. Offline captures do not prove live persistence or reconnect behavior; server persistence already belongs to the existing talent system.
