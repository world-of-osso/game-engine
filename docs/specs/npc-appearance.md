# Authored NPC rendering

> Root `src/` paths below name files deleted with the [retired Bevy client](godot-conversion.md#retired-bevy-client-user-decision-2026-10-02).

Replicated NPCs render the appearance selected by their creature display data. Runtime integration lives in `src/rendering/character/npc_appearance.rs`; [character rendering](../wiki/systems/character-rendering.md#authored-npc-appearance) describes the pipeline. Cache production has a separate [importer contract](npc-appearance-importer.md).

**Material PASS** means complete native mip-0 RGBA bytes and dimensions match the DB2/BLP oracle in every sampled M2 batch/slot. Ordinary skins additionally match the complete authored compressed upload and format before decoding. Their independent source Image uses Godot's DXT expansion, which differs from CPU image-blp by ±1 channel value; no tolerance is used. **Visible PASS** additionally requires at least one enabled batch on that genuine spawn. This is material-image proof, not rendered-scene pixel parity or acceptance at original world locations. FAIL means the corresponding acceptance gate is unproven, not necessarily a client defect. N/A means the read-only current-world audit found no consumed M2 slot, not that the DB2 declaration or format is unsupported.
