## How it works

### Default root command

Root `cargo run`/`rd` builds the std-only debug `game-engine-launcher`, uses executable `GODOT_BIN`, else pinned Godot 4.7.2 at `${XDG_CACHE_HOME:-~/.cache}/game-engine/godot/4.7.2/` (downloaded from the official release and SHA-512-verified on first use, installed atomically; a checksum mismatch installs nothing and prevents the build), invokes `python3 scripts/depot-build.py --root <checkout>` for the native extension, and after that build runs `--headless --import` once when `godot/.godot/extension_list.cfg` is missing (a failed import keeps its status and prevents launch), then execs Godot with the `godot/` project, raw forwarded arguments, and the native debug dependency path. It does not start a server or fall back to Bevy. The root workspace defaults only to the launcher; the preserved Bevy package requires explicit `-p game-engine`/`--bin game-engine`, and `godot/` remains a separate workspace. `run-tests.sh --workspace` covers existing root plus launcher tests; Godot workspace tests remain separate. `41036dfe` reports seven launcher process-boundary tests before root integration/refactoring.
