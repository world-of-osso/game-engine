# Damage meter

Retail's built-in damage meter window (`Blizzard_DamageMeter`, 12.x), with the user's top-left placement in both Modern and Forever (decision 2026-10-05), not a Retail-position parity requirement. The server computes the damage sessions (game-server `docs/specs/damage-meter.md`) and sends `DamageMeterSnapshot`; the client shows them. The snapshot carries damage only: healing, interrupts, dispels and deaths are counted on the client from the `CombatLogEvent`s it receives.

Client: `godot/ui-model/src/damage_meter_data.rs` (session selection, rows, number formats), `godot/ui-model/src/ui/screens/damage_meter_component.rs` (window), `godot/rust/src/damage_meter.rs` (host, actions, fixture state). Fixture: `godot/tests/damage_meter.gd`.

## What it must do

- [x] Preset `DamageMeter` defaults sit at UIParent's top-left, mirroring the minimap's top-right margins per skin ([HUD presets](hud-edit-mode.md#godot-client-presets)); saved custom placements retain their positions. User choice 2026-10-05, not Retail's default-position contract. Modern remains 400x140 with 16 px bars 4 px apart (DamageMeter.xml:11-15; EditModePresetLayouts.lua:857-863): the preset raw values FrameWidth 100, FrameHeight 20, BarHeight 1, Padding 2 over the slider minimums (EditModeSettingDisplayInfo.lua:1127-1175, `ConvertValueDiffFromMin`/`ConvertValueDefault`). Forever retains its 450x214 skin and [reference rows](forever-chat-meter-chrome.md). Shown in the world only.
- [x] Header (`DamageMeterSessionWindowTemplate`, DamageMeterSessionWindow.xml): `ui-damagemeters-header-bar`; the session timer `"[MM:SS] "` at +15,-9 only while the player is in combat (`ShouldDisplaySessionTimer`, `SetSessionDuration`); the type dropdown arrow and "Damage Done" (the default type, DamageMeter.lua:92-97) after it; on the right the session dropdown ("O"/"C"), settings and minimize button art.
- [x] The window starts on `Overall` (DamageMeter.lua:80). Clicking the session dropdown opens a menu with `Current Segment` and `Overall` radios (DamageMeterSessionWindow.lua:433-437); choosing one switches the session and closes it.
- [x] Rows (`DamageMeterSourceEntryTemplate`, Default style): the server's rank order, "N. Name" (`DAMAGE_METER_SOURCE_NAME`) left, Compact numbers "damage (dps)" (`DAMAGE_METER_ENTRY_FORMAT_COMPACT`, the preset `Numbers`) right in NumberFontNormal (ARIALN 14 outline); the StatusBar fill is `UI-HUD-CoolDownManager-Bar` tinted by `RAID_CLASS_COLORS`, filled by damage over the session's highest, over `ui-damagemeters-bar-shadowbg`/`-shadowedge`. Numbers use `AbbreviateLargeNumbers` as last shipped in Lua (UIParent.lua:774-785).
- [x] `damagemeters-background` behind everything at 50% (preset BackgroundTransparency 50).
- [x] Types (`Enum.DamageMeterType`, DamageMeterConstantsDocumentation.lua:102-112): Damage Done (default, DamageMeter.lua:92-97), Healing Done, Interrupts, Dispels, Deaths, named by `DAMAGE_METER_TYPE_*`. Modern: clicking the type dropdown (`DamageMeterTypeDropdown`, 25x25 at the arrow) opens the type menu under it and the header shows the type's name. Forever: header tabs "DPS" (Damage Done) and "HPS" (Healing Done), the selected one bright; the chart button's menu lists the types beside the sessions, and another type shows its name as a third bright label. Choosing a type or a session closes the menus. Open menus are drawn over the rows they cover (Dialog strata) and stay inside the window's width at any [layout size](hud-edit-mode.md): Forever's type menu sits beside the session menu, or under it when the window is too narrow for both; a menu taller than the window hangs below it. Both menus remain on screen at the top-left preset positions at 1920x1080 and 1366x768; menu behavior and art are unchanged.
- [x] Healing Done rows: like damage rows, "N. Name" and "healing (per second)", class-coloured, ranked by healing; healing is the heal less its overheal, per second over the selected session's duration.
- [x] Interrupts and Dispels rows: "N. Name" and the count alone (`DAMAGE_METER_TYPE_SUPPRESS_VALUE_PER_SECOND`, DamageMeterSessionWindow.lua:29-32), ranked by count; a dispel counts once per removed aura.
- [x] Deaths rows (DamageMeterEntry.lua:562-605): one per player death, the name without a rank, a full class-coloured bar, and the time into the session ("3m 22s", `deathTimeFormatter`) in Current, nothing in Overall. Newest first (Retail's order is `C_DamageMeter`'s, not in its Lua).
- [x] Clicking a death opens its recap in the window (`OpenDeathRecapUI`, DamageMeterSessionWindow.lua:967-972; Retail opens the separate `DeathRecapFrame`): the header reads "Death Recap" (`DEATH_RECAP_TITLE`), the rows are the last 5 damage and healing lines on that player within 10 s before the death, newest first (the killing blow first, Blizzard_DeathRecap.lua:340): "spell by source" (`DEATH_RECAP_CAST_BY_TT`; "Melee" for a swing, `ACTION_SWING`; the type for environmental damage, `ACTION_ENVIRONMENTAL_DAMAGE_*`, :116-119), "-amount (seconds before death, from the server's `timestamp_unix_ms`)" for damage (Blizzard_DeathRecap.lua:162, "%.1F" :72-74) in red, "+amount (...)" for healing in green. Retail's recap lists damage only; healing is listed because the user asked for it. Clicking a recap row, or choosing a type or session, closes it.
- [x] A type with no counted lines shows no rows.
- [ ] Group gap: the server sends a combat log line only to the owners of its source and target (game-server `spell_cast/mod.rs` `log_event`), so the client-counted types list the local player's own healing, interrupts, dispels and deaths, and what others do to the local player. A group member's healing of others, interrupts, dispels, deaths and recap are missing until `DamageMeterSnapshot` carries them per type (Retail: `C_DamageMeter.GetCombatSessionFromType(sessionType, damageMeterType)`).
- [x] Clicking an Interrupts or Dispels row opens that player's spell breakdown in the window (`ShowSourceWindow`, DamageMeterSessionWindow.lua:967-979; Retail opens the separate `DamageMeterSourceWindow`): one row per interrupted spell or dispelled aura (`CombatLogEvent::extra_spell_id`, CLEU `extraSpellId`), the spell's name (`DamageMeterSpellEntryMixin:GetNameText`, DamageMeterEntry.lua:706-711) and its count, most first, in the player's class colour. The header keeps the type's name. Clicking a breakdown row, or choosing a type or session, closes it. Which spell `C_DamageMeter` keys these rows by is not in the UI files; the interrupted spell and the removed aura were asked for.
- [x] Overall lists every counted line since world entry (the server's Overall likewise counts every damage line; one outside combat starts its own session, game-server `damage_meter.rs` `record`). Current lists the lines that arrived while the snapshot's `Current` session ran.
- [ ] Current assigns lines by client arrival time against the snapshot's session id, duration and active flag; a line arriving more than 0.5 s before the session's computed start is left out of Current. Healing per second in Overall divides all healing by the combat time of the sessions.
- [ ] Retail's `Dps`/`Hps` types (per-second value first), `Absorbs` and the damage-taken types are not offered; the type menu is one flat list, not category submenus.
- [ ] The dropdown menus' art is a plain dark panel, not `MenuStyle2`; past sessions ("Combat N"), the settings menu, minimize, resize and moving are not implemented.
- [ ] Modern spec icons (`ShowSpecIcon` 1) are not drawn: the snapshot has no spec. Modern rows start at the bar's left edge as with icons off. Forever uses the supplied class identity; [reference chrome and provenance](forever-chat-meter-chrome.md).
- [ ] Retail's C `AbbreviateLargeNumbers` may format differently from the old Lua one.
- [ ] Only the rows that fit the window's height are shown (Forever: 5 at the preset size, [geometry](forever-chat-meter-chrome.md)); the scroll box, scroll bar and pinned local-player row (`AlwaysShowsLocalPlayer`) are not implemented.
- [ ] The per-spell breakdown of Damage Done and Healing Done (`DamageMeterSourceWindow`) is not implemented; the snapshot already carries each source's damage spells. A recap longer than the visible rows cannot happen (5 rows).

## Current-target threat (2026-10-05)

- Threat is offered in the type menu (Forever shows its existing third-type label). This is a requested Details-like extension: Retail `Blizzard_DamageMeter/DamageMeterSessionWindow.lua:1-5,34-44` has no threat category. Threat follows the selected target, not Current/Overall damage sessions.
- `ThreatUpdate` supplies every unit on an engaged creature's table, descending raw threat, names/classes, raw threat, status and raw/scaled percentages. Rows show raw percentage relative to the current victim and a class-coloured bar relative to the highest threat. The local player's row retains its local identity.
- Empty updates remove the creature's table. Combat end (true-to-false transition) and world exit clear cached threat; changing target selects its table or an empty list immediately. Threat messages arriving before replicated combat entry are retained but hidden until the combat flag arrives.
- Retail threat API/indicator reference: cached `Blizzard_UnitFrame/Mainline/UnitFrame.lua:998-1045`, `TargetFrame.lua:488`, `TargetFrame.xml:325-345`. The native target-frame state has no threat indicator, so this task adds none.
- Server mechanics and transmission: game-server [creature-aggro spec](../../../game-server/docs/specs/creature-aggro.md), TrinityCore a352b1fa `ThreatManager.cpp:733-760,829-875` (`ThreatUpdate` / `ThreatClear`).
