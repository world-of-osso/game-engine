# Benilla Asset Field Inventory

Static comparison of Benilla's asset readers **and their consumers** against the current Godot game-engine. Benilla is useful for field meanings, reference-address leads and concrete algorithms; it is not a replacement specification for our newer assets. Most large subsystems already exist here. The most actionable differences are lost or unbound field semantics, not entire missing model/terrain loaders.

- Benilla targets **WoW 1.12.1 / build 5875**. Its MD20 reader accepts versions 256–263; that does not make their layouts equivalent to our newer M2/SKIN/SKEL files. Our camera reader, for example, explicitly accepts versions 272–274.
- Benilla's vendored reference-table pin is `c854c4e9f3dbae98c3d7857cf0cca92bb0cdbf5a` (`reference/PIN`). Address annotations below are Benilla's research claims, **not independently authenticated original-client observations**.

Proof level throughout: **static source inspection**. No client/reconstructed source/Lua was executed, imported, built or installed; no asset extraction or visual/native-runtime comparison was run. Existing test files are pointers for future verification, not fresh passing-test evidence. Rows cover the named fields/families below, not every byte, every flag or every renderer variant.

Status vocabulary:

- **Gap**: a specific parser/adapter/runtime boundary demonstrably loses or does not bind the named input.
- **Partial**: a supported family has a narrower identified path or policy.
- **Present**: source has the named mechanism; not a universal fidelity claim.
- **Unknown**: insufficient paired evidence; not an implementation task.

`E/path:lines` and `B/path:lines` identify files relative to the roots above. Code revisions, rather than wiki descriptions, govern the matrix.

### Suggested investigation order

1. **Terrain binding/state:** ADT-1 IMPASS propagation and ADT-2 ground shadow binding. Both have concrete local loss boundaries and Benilla consumers to inspect.
2. **WMO material binding:** WMO-1 SIDN and WMO-2 opacity. Check matching modern assets/reference first; then choose real nonzero-color/nonconstant-opacity fixtures.
3. **WMO authored selection:** WMO-5 footsteps, then WMO-4 shared-cell overlap. Avoid turning Benilla's static shared-cell ownership into a spec.
4. **M2 camera tracks:** M2-1 when animated model/cinematic cameras are required. Static portrait snapshots are already intentional supported behavior.
5. **Conditional expansion work:** weather, legacy MCLQ and non-DXT authored mip preservation. Requirements and real affected assets determine priority; no blanket format rewrite is justified.

These are research priorities, **not approved implementation scope**. No patch, build, deploy or native acceptance is claimed.

## 4. Reference limitations and safe use

Use Benilla to identify a field, its downstream selection, a source address and a behavioral counterexample. Confirm the **same asset generation**, then write a concrete byte/scene fixture before implementation. A parsed field is not proof it reaches the renderer; a familiar name is not proof it means the same thing in two builds.

Important deliberate differences, which must not become our native specification:

- **Water:** `B/crates/benilla-assets/src/shaders/liquid.wgsl:18–20` selects a shader/specular path differing from its reference defaults; `world_assets/images.rs:69–76` flattens water-frame DC. `B/crates/benilla-formats/src/models/wmo/group.rs:18–23` substitutes position UVs for authored magma/slime pairs.
- **Lighting:** `B/crates/benilla-assets/src/shaders/wow_model.wgsl:668–670` clamps a reference intensity that can exceed one; `B/crates/benilla-world/src/lighting/global_light.rs:82–84` and `resolve.rs:164–166` omit reference byte quantization. Shared doodad material animation phases are another stated deviation (`doodad_anim/mat_anim.rs:185–188`).
- **Visibility/collision:** `B/crates/benilla-world/src/wmo_portal/seed.rs:21–24` permits a camera-face retry beyond the reference behavior. Shared-liquid lowest-group dedup above is not the reference's dynamic parity decision.
- **Streaming and malformed input:** `B/crates/benilla-world/src/terrain_stream/window.rs:7–11` keeps whole tiles plus a band instead of the reference chunk window; `B/crates/benilla-blp/src/lib.rs:232–237` zero-fills short payloads rather than consuming stale bytes. Neither is a transferable file-format rule.

Benilla's `docs/DEVIATIONS.md` is useful but not sufficient alone: read the actual parser, `benilla-formats` adapters, asset loader and renderer. Many WMO fields live in adapters, not `benilla-wmo`. This inventory copies no upstream implementation or game assets; any future source reuse is separate work with the applicable license notices and provenance retained.
