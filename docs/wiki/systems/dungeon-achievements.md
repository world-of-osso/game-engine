## State and rendering

`godot/network/src/lib.rs` subscribes to DungeonProgress on InstanceChannel and catalog/live state on AchievementChannel. `account.rs` dispatches decoded messages into `DungeonObjectives` and `AchievementWindow`, and queues page continuations. The frame tick sends requests through NetworkBridge on AchievementChannel.

Dungeon snapshots carry no dungeon name: account dispatch resolves `MapName_lang` from the local pinned Map.csv. The first snapshot fixes map/copy/difficulty identity until a transfer. The Scenario-style module precedes watched quests; their order and the container anchor stay unchanged. Empty snapshots and disconnect clear objectives. Unknown optionality is not labeled mandatory.

AchievementWindow retains categories, achievement and criteria pages. The native RegistryUi inserts the complete cache into SharedContext; generation updates rebuild its screen. Categories use parent/order, achievements use exclusive ID cursors, criteria merge by tree ID and sort by authored order. Native category and row ScrollBoxes show loaded cursor pages. Reaching the row list's bottom requests its next cursor, with pending-query deduplication; appended pages preserve expansion and scroll position. Changing category/filter/standalone detail returns to the top. Catalog pages arrive only on demand. Earned dates render UTC; absent dates stay unknown. Summary is the initial view. Its points, full eligible counts, category-ancestor totals and newest three earned rows come from the server, independently of loaded pages. All/Account/Character query scopes use the authentic 0x20000 account flag; the visible tabs and completion filters follow Retail as described below. Live updates invalidate Summary and cached categories and request the visible category, selected own-state detail or active search again.

Full snapshots are the per-connection baseline (`AchievementWindow::snapshot`); `AchievementDelta` (2026-10-17) reduces against it to the same earned/progress state and the same invalidation as the corresponding full snapshot. Earned IDs are replaced verbatim (server order: character ascending, then account-wide), progress rows keep the server's ascending `definitions` order. Earned alerts remain `snapshot: None` updates, so they never establish a baseline. The achievement relay sorts pages, updates and deltas together by AchievementChannel message ID; a delta without a baseline fails dispatch explicitly. [Contract](../../specs/dungeon-achievements.md#dungeon-and-window-lifecycle).

Tracking uses a selected row's native Track/Stop tracking control; only unearned achievements can be watched (maximum ten). The native ObjectiveTracker inserts its Achievements module after quests, with server criterion counters and unevaluated labels. Account/realm/character-local preferences store IDs only; re-entry requests authoritative rows, and live updates refresh watched IDs even when AchievementFrame is closed. Newly earned rows stop tracking.

Statistics uses the authentic flag1 catalog and raw, unclamped supported counters. Unsupported statistic types remain Unevaluated. Search queries the full faction/scope-eligible server catalog by title/description (including statistics), not client-loaded pages; results are term/scope correlated and ID-cursor paged. Native links in the earned chat line and toast open the viewer's own server state. Shift-click inserts ID/name markup at the existing chat caret; no invented GUID/comparison payload. Online comparison now queries authoritative target account/character state through the endpoint described below.

Launcher and micro-menu share AchievementMicroButton dispatch. ToggleAchievements uses persisted bindings. CloseAllWindows owns Escape. The Godot branch previously had no achievement subscription/toast host; completed wire payloads now queue six-second native alerts.

Modern uses local UI-Achievement-Category-Background (130652), AchievementBackground (235397) and Shields (130666; plural file named by Mainline XML, not the different singular130665 asset). Forever uses active-skin flat panel chrome and its metal sheet. Earned alerts use Mainline's 300×101 template, atlas1771/FDID4035524 regions, authoritative earned icon, 52×52 icon, point shield and centered title/name; both skins preserve the same elements. The legacy uncropped FDID130650 sheet is not an alternate alert path. Category button backgrounds, icon frames, point shields and achievement row backgrounds crop the Mainline XML sheet regions; a category-button strip is never stretched across the sidebar. Summary captions are children of their bars, drawn after fills so completed pixels cannot cover text. Assets are local CASC/cache only.
