# Floating combat-text parity audit

This page compares the outgoing world text and incoming `Blizzard_CombatText` paths with the locally cached Retail sources. The requested `/syncthing/Sync/Projects/wow/wow-ui-sim` path is not mounted here; the identical local reference is `/home/osso/.cache/wow-ui-sim/blizzard-ui/retail`. The game-engine change is skin-neutral. Retail and Forever combat-text Lua/XML, constants and the world font are byte-identical here except for Forever's compatibility wrapper at `Shared/CombatText.lua:469-474`.

## Runtime options

`godot/core/src/combat_text_options.rs` stores the mapped CVar values under `hud.combatText` in the existing options file, using the Retail CVar names. Defaults match the cached table (`enableFloatingCombatText=0`, damage/healing/periodic/pets on, avoidance/reductions/friendly-healer labels off, float mode 1, screen heights and scale above). This is a persisted options surface, not a general live CVar registry or settings panel; editing the file takes effect on the next client start. Unmapped self notifications (auras, power gains, combat state, low-health/mana, honor, reputation, combo/rune, reactive spell text) need event kinds not carried by the current protocol.
